# A(민서) 측정 시제품 v7.8 — 공유·검토용

## 실행
저장소 루트에서 `uv run --with certifi python web/dev/aPdfMultilineV78/review/setup_runtime_assets.py`를 실행합니다. 이미 기존 v7.8 폴더에 자산이 있다면 해시 확인 후 다시 받지 않습니다. `uv run nundojang`으로 서버를 켜고 http://localhost:8000/dev/aPdfMultilineV78/index.html 을 엽니다.

두 쪽 시험 PDF 불러오기 → 안정된 받침·편안한 높이·실제로 잰 카메라–눈 거리 입력 → 카메라·모델 준비 → 기준 측정 시작. 점9개로 개인 모델을 설정하고, 점6개로 가로 경계를 점검합니다. 회차 사이 점6개는 모델 재학습이 아닌 경계 조정입니다.

1. 1쪽 왼쪽 네 줄 한 번 → 오른쪽 네 줄 한 번.
2. 같은1쪽 왼쪽 네 줄만 두 번.
3. 2쪽 왼쪽 네 줄만 두 번.
4. 2쪽 오른쪽 네 줄만 한 번. 준비점도 오른쪽입니다.

준비점은2초 보고 클릭하지 않습니다. 각 읽기를 마친 뒤 클릭 또는 스페이스로 넘어갑니다. 자연스럽게 깜빡입니다. 후보를 채우려고 추가로 읽지 않습니다. 종료 후 samples/events/diagnostics 세 파일을 로컬에 저장합니다. 원본 영상은 저장하지 않지만 samples에는 파생 눈 영상 특징 수치가 있으므로 실제 참가자 로그를 저장소에 올리지 않습니다.

## 확인 결과와 범위
민서 님의 실제 맥북·Chrome, 거리52cm, 본문16px·줄높이32px·가로 영역 약496px에서 4회차를 확인했습니다. 세부 수치는 review/RESULTS_KO.md. 현재는 두 원본 페이지·각 영역 네 줄인 텍스트 PDF를 사용하는 진단 화면입니다. 실제 동의·서명 버튼은 활성화하지 않습니다. 표·그림·스캔·복잡한 다단 PDF나 짧은 줄 전체 지원을 주장하지 않습니다.

같은 영역 안에서 일부 줄을 반복해도 후보가 누적될 수 있습니다. 80%의 고유 줄을 읽었다고 확인하지 않습니다. 초기 경계를 그대로 유지하면 후보 누락이 늘었고 중간 점검에 아직 의존합니다. 매번18초 점검하는 절차를 최종 사용 흐름으로 확정하지 않았습니다.

## C(찬혁) 연결 검토
review/INTEGRATION_KO.md의 입력·출력·좌표·후보 의미 차이를 먼저 확인합니다. 이 폴더를 추가하면 독립 시제품을 실행할 수 있지만 기존 제품 화면의 tracker/detector가 자동 교체되지는 않습니다. 공통 계약 변경과 새 경로 소유권은 C 검토 항목입니다.

Node.js20 이상이 있다면 `node --test web/dev/aPdfMultilineV78/review/tests/handoff.test.mjs`로 합성 검증을 실행할 수 있습니다. 실제 카메라 성능 평가가 아닙니다. 자산 해시 확인은 setup_runtime_assets.py --check-only를 사용합니다. worker를 재빌드하려면 review/에서 npm ci 후 node build.mjs를 실행합니다. 배포된 worker와 재빌드 결과의 해시는 별도로 확인해야 합니다.
