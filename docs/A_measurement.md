## 현재 상태와 이번 교체 (v0.8.4-r1 / PR #9 검토 반영)
- A(민서)의 기존 MediaPipe 측정·줄바꿈 후보 검출 방식에서 PR #9의 세 가지 오류를 수정합니다. 이번 패키지 교체 대상은 `web/modules/eyeTracker.js`, `web/modules/movementDetector.js`, 이 문서입니다.
- `eyeTracker.js`의 `trackerVersion`은 `a-measurement/0.4.2`입니다. 두 모듈의 진단에 `implementationRevision: pr9-fixes/0.1.0`을 추가합니다. 기존 측정 화면의 표시 버전은 v0.8.4로 유지됩니다.
- v0.8.4의 눈꺼풀 진단 특징은 실제 민서 님의 맥북 자료에서 기록된 것을 확인했습니다. 그 특징으로 상하 구분이 개선됐다는 근거는 아직 충분하지 않습니다. v0.8.0의 7번 상하 기준은 약 60cm 이상/45cm에서 통과하지 못했으며, 8번의 실제 실행 자료는 없습니다.
- 별도 WebGazer pilot v0.1.0을 작성했으나 해당 새 화면의 실제 맥북 시험 자료는 아직 없습니다. 공식 데모에서 민서 님이 보고한 69%/83%는 이 별도 시험의 결과가 아니며 읽기 비율이나 PDF 줄 정확도가 아닙니다.
- 새 오류 수정본은 합성 입력·카메라/MediaPipe 모의 시험과 기존 P01 기록 8개의 재생을 확인했습니다. 수정 후 새 맥북 실행·새 사람 시험은 아직 확인 전입니다. 동현 님 기록은 사용하지 않았습니다.
- 공통 Sample/Event 규격과 CSV 열, 측정 식, 검출 임계값, C(찬혁) 제품 파일·공통 config는 변경하지 않습니다. 아래 과거 버전 기록은 해당 시점 상태입니다.

### PR #9 세 가지 수정
1. `clear()`는 무효 샘플·프레임 공백에서 신호 이력만 비웁니다. `lastEmit`은 세션·페이지·구간 문맥 변경 또는 명시적 `reset()`에서만 초기화합니다. 무효 구간을 가로질러 관측하지 못한 줄바꿈을 복원하는 기능은 아닙니다.
2. 최고점 대비 되돌아온 크기가 `minAmplitudeX × 0.2` 아래로 작아지면 `returnStart=null`로 취소합니다. 작은 흔들림 뒤 머문 시간을 실제 복귀 시간에 합산하지 않습니다.
3. `onSample`은 추론용 try 밖에서 호출합니다. 소비자 오류는 원래 예외로 전달되고 `inference_failed`로 재분류하지 않으며, 진단의 `sampleCallbackErrors`에 셉니다. finally에서 다음 영상 프레임 예약을 보장하되 콜백 안에서 stop/destroy하면 다시 예약하지 않습니다. 진짜 추론 오류의 보고·카메라 중지 동작은 유지합니다.

### 버전과 C(찬혁) 연결
- 알고리즘 이름은 `return-sweep/0.1.0-pilot2`로 유지하고 구현 수정 번호를 별도로 둡니다. 사건의 `detectorVersion`은 기존처럼 호출자가 넘긴 config 값을 사용합니다. C(찬혁)가 제안한 초기 설정을 이 패키지에서 덮어쓰지 않습니다.
- `sampleCallbackErrors`와 `implementationRevision`은 getDiagnostics의 보조 항목입니다. 공통 계약 Sample/Event의 필수 키를 늘리지 않습니다. 소비자 예외를 새 onError 코드로 전달하지 않으므로 기존 C(찬혁)의 onError 분기를 추가할 필요는 없습니다. 오류가 없어진 것으로 숨기는 방식도 아니며 브라우저 예외로 확인할 수 있습니다.
- GitHub 병합 여부·B(규태)/C(찬혁)의 최신 진행 상황은 이번 패키지에서 확인하지 않았습니다.

기준: 사용자가 제공한 NunDojang-main.zip. ZIP에는 정확한 Git commit 메타데이터가 없어 commit은 미확인. 공통 스크립트 v2.0.2, 계약 gazegate-contract/1.1.0. 실제 맥북 실행·측정 결과는 아직 없음.

### 이번 변경 범위
- eyeTracker.js: 실제 MediaPipe 초기화·카메라·샘플·시작/중지/해제.
- measurement.html / measurement.js: A 독립 점검, 양쪽 눈 그래프·CSV·진단 저장.
- 이 문서. C 소유 파일과 movementDetector.js는 수정하지 않음.
- 제품의 MODE는 검출기가 아직 mock이므로 계속 mock일 수 있음. A 독립 화면의 실제 샘플 측정과 제품 전체 실측 판정을 구분.

### 측정 식·랜드마크
MediaPipe의 정규화된 입력 영상 좌표 사용. 해부학적 왼눈: 눈 양끝 362·263, EAR 위아래 쌍 385–380, 387–373, 홍채 중심 473. 오른눈: 양끝 33·133, EAR 쌍 160–144, 158–153, 홍채 중심 468.

- x = (홍채 중심 x - 양끝 x의 작은 값) / abs(양끝 x의 차이).
- EAR = (첫 세로 쌍 거리 + 둘째 세로 쌍 거리) / (2 × 양끝 거리).
- EAR 거리는 x에 실제 영상 너비, y에 실제 영상 높이를 곱한 2D 픽셀 거리. 영상 종횡비를 보정한 뒤 비율 계산. z는 사용하지 않음.
- 홍채 y는 미구현으로 두 눈 모두 null. headMotion도 미구현으로 null.
- 미리보기만 CSS로 좌우 반전하며 입력 영상·샘플은 반전하지 않음.
- 눈 폭 2픽셀 미만, 필수 좌표 누락, 상대 x가 0~1 밖, 양쪽 중 어느 한 눈의 EAR < 0.10이면 eye_unreliable. 좌표를 잘라내지 않음. 무효시 모든 홍채 x/y는 null, 계산 가능한 EAR은 남김.
- EAR 0.10은 초기 구현의 눈 검출 품질 기준이며 실제 보정·검증 전. 깜빡임 이벤트나 횟수 기준이 아님. 이 조건만으로 눈 감김/가림을 완벽히 판별하지 못함. 안경·고개 회전 영향과 임계값 적합성은 점검 필요.
- 얼굴 없음은 no_face. numFaces:1이므로 복수 얼굴 확인은 미구현. 여러 사람이 들어오면 측정하지 않도록 사용자 안내.

### 실행 설정
@mediapipe/tasks-vision 0.10.32, 공식 face_landmarker float16/1, VIDEO, CPU. detection/presence/tracking confidence 각각 0.5. 요청 카메라 1280×720, ideal 30fps, audio:false. 실제 해상도·트랙 설정·처리 빈도는 진단값으로 확인하며 30fps를 보장하지 않음. detectForVideo는 메인 스레드의 동기 처리. 영상 currentTime이 바뀐 프레임만 처리.

create에서 모델 준비, start에서 카메라 요청. Sample의 tMs는 추론 직전 performance.now()-호출자 sessionT0. 같은 세션의 재개시 seq·시간 원점 유지, 다른 세션에서만 seq 초기화. stop 여러 번 가능, 트랙 정리, 늦은 카메라 권한 결과도 취소 처리. 모델 호출용 타임스탬프는 세션과 별도로 객체 수명 동안 증가.

## v0.2.0 — 새 영상 프레임과 응시/읽기 점검

### 기존 관찰
사용자 제공 좌우 CSV/진단에서 카메라 트랙 설정은 1280×720·30fps, 분석 빈도는 약 60회/초. 원인은 확정하지 않았으며 카메라의 실제 촬영률 60fps를 뜻한다고 해석하지 않음. v0.1.0의 requestAnimationFrame/currentTime 방식은 이 버전에서 아래 방식으로 대체.

### 프레임 처리
- requestVideoFrameCallback으로 새 영상이 compositor에 제출된 알림을 받아 분석. 성능에 따라 모든 촬영 프레임을 처리한다는 보장은 없음.
- metadata.mediaTime이 직전보다 증가하는 경우만 추론. 중복/역행 알림은 건너뛰고 duplicateFramesSkipped에 기록.
- presentedFrames의 증가 차이에서 알림 사이 관찰하지 못한 표시 프레임 수를 진단에 기록. 센서 손실 프레임 수를 의미하지 않음.
- Sample.tMs는 종전처럼 추론 직전 performance.now()-sessionT0. mediaTime을 세션 시간으로 대체하지 않음.
- stop은 cancelVideoFrameCallback과 카메라 트랙 정리. 재개시 미디어 시각 기준은 초기화하지만 같은 세션 seq/tMs 원점 유지.
- API 미지원이면 명확한 오류. 약 60회 rAF로 조용히 되돌아가지 않음.
- 요청 카메라 설정은 그대로 ideal1280×720·ideal30fps. 특정 팀원 맥북의 카메라 사양을 기준으로 하지 않음.
- 진단: frameScheduler, callbackCount, duplicateFramesSkipped, presentationFramesNotObserved, lastVideoFrame 추가. 기존 Sample·CSV·공개 함수 규격은 변경하지 않음.
- 장치 고유 ID(deviceId/groupId)는 새 진단 JSON에서 제외.

### 점검 화면
선택 가능한 시험: center / reading. 사용자가 시험을 선택하고 새 기록 → 시작. 첫 Sample부터 준비 3초. 유효 프레임 여부와 무관하게 실제 시간으로 준비·종료를 관리하고 원자료는 무효 포함 저장.
- center: 준비 뒤 +를 15초 응시하면 자동 종료.
- reading: 준비 뒤 10줄의 자체 작성 글을 보여줌. 위→아래 한 번 읽고 마지막 줄 뒤 종료 버튼. 90초 초과는 interrupted.
- 글은 PDF가 아닌 A 점검용 HTML 고정 줄. 자연 읽기 측정 가능성을 먼저 점검하는 용도이며 제품 PDF 레이아웃/줄 수/점수 구현을 대체하지 않음.
- 다른 탭 이동·창 크기 변경·수동 중지는 interrupted. 새 기록으로 다시 시험, 중단된 기록도 내보내기 가능.
- 글 너비 초과 또는 화면 아래로 잘리면 오류 안내하고 중단. 실제 Mac 배치 확인 필요.
- 준비/활성/종료 시각·종료 사유·예정 행동 라벨·화면 크기·줄 배치를 진단 JSON test 등에 기록. 지시한 행동이지 실제 읽기 정답 라벨이 아님. CSV 열을 추가하지 않고 diagnostics와 sessionId로 연결.
- paired 파일명: center-<sessionId>.csv / center-diagnostics-<sessionId>.json, reading도 같은 방식.

## v0.6.0 측정 상태·얼굴 기준점 변화 진단 (2026-11-05)

### 목적과 범위
현재 측정에서 눈 위치 기록이 끊기는 상황과 얼굴 기준점이 움직이는 상황을 구분할 자료를 남긴다.
자동 머리 흔들림 보정이나 거리(cm) 추정, 3D 고개 자세 추정은 추가하지 않는다.
현재 사용자 지시에 따라 기존 다른 참여자의 기록은 이후 개발 비교·검증에서 제외한다.
현재 민서 자료에 대한 개발 점검이며 다른 사람에게 적용되는 성능을 확인한 결과가 아니다.

기준 입력은 사용자가 제공한 eyeTracker.js·movementDetector.js·measurement.html·measurement.js이며
모두 직전 v0.5.0 파일과 바이트가 일치했다. 정확한 Git commit은 제공되지 않았다.
공통 계약 gazegate-contract/1.1.0, 공통 시작 문서 v2.0.2를 유지한다.

### tracker 내부 진단 확장
eyeTracker 버전 a-measurement/0.3.0.
MediaPipe가 이미 추출한 33·263 두 바깥 눈꼬리 좌표를 사용한다. 홍채 좌표로 얼굴 위치를 정의하지 않는다.
영상 너비 w, 높이 h에 대하여 다음 값을 계산한다.

- centerXPx = (x33 + x263) * w / 2
- centerYPx = (y33 + y263) * h / 2
- eyeSpanPx = hypot((x263 - x33) * w, (y263 - y33) * h)
- rollDeg = atan2((y263 - y33) * h, (x263 - x33) * w) * 180 / pi

rollDeg는 두 기준점을 이은 선의 영상 평면 내 각도이며 실제 3D 머리 회전의 정답이 아니다.
이 값은 반전하지 않은 카메라 영상 좌표다. 미러링된 영상 미리보기와 방향 해석을 혼동하지 않는다.
기준점이 없거나 좌표가 비정상일 때 geometry=null. 과거 프레임 값을 대신 사용하지 않는다.
눈 위치의 유효성 검사와 얼굴 기준점 진단은 별도이므로 eye_unreliable 프레임에도 geometry가 있을 수 있다.

getDiagnostics().lastFrameDiagnostics에 sessionId, seq, tMs, faceGeometry를 추가한다.
Sample 콜백 전에 동일 프레임의 진단을 갱신하고, dev 화면은 세 식별값이 모두 일치할 때만 연결한다.
공개 createEyeTracker 인자·반환 메서드, EyeSample·MovementEvent의 키·단위·의미는 그대로다.
EyeSample.headMotion은 계속 null. 이 진단은 공통 headMotion의 구현으로 취급하지 않는다.
공통 headMotion에 반영하려면 후속 단계에서 C와 interface.md에 식·단위·경계값을 합의해야 한다.

### 진단용 비교 기준
좌우 기준 측정이 기존 품질 검사를 통과했을 때만 faceReference를 함께 만든다.
기준 측정의 실제 측정 구간에서 눈 위치와 얼굴 기준점이 유효한 프레임을 사용한다.
최소 60개, 첫 프레임~마지막 프레임 2000ms 이상, 동일한 영상 해상도가 필요하다.
중심 x·y, 눈꼬리 간격, 영상 내 기울기는 각각 중앙값으로 대표한다.
이 요건은 진단 기준의 기록 충분성 조건이며 머리 안정성의 정확도를 보증하지 않는다.
얼굴 기준 기록이 부족해도 기존 좌우 기준의 accepted·minAmplitudeX 산식은 바꾸지 않는다.
자세 점검 모드는 얼굴 비교 기준이 있는 경우에만 시작한다.

비교 식과 화면 표시용 초기 경계값:

- shiftXEyeSpans = (현재 centerXPx - 기준 centerXPx) / 기준 eyeSpanPx
- shiftYEyeSpans = (현재 centerYPx - 기준 centerYPx) / 기준 eyeSpanPx
- 위치 변화: hypot(shiftXEyeSpans, shiftYEyeSpans) > 0.15
- eyeSpanChangeFraction = 현재 eyeSpanPx / 기준 eyeSpanPx - 1
- 간격 변화: abs(eyeSpanChangeFraction) > 0.15
- rollChangeDeg = 현재 rollDeg - 기준 rollDeg
- 영상 내 기울기 변화: abs(rollChangeDeg) > 8도

서로 단위가 다른 항목을 하나의 머리 움직임 수치로 합치지 않는다.
위 15%·8도는 개발용 표시 경계값이고 아직 검증되지 않았다. 눈꼬리 간격 변화는 거리 변화로 확정할 수 없다.
카메라 영상 해상도가 기준 때와 달라지면 비교 불가로 표시한다.
영상 좌표로부터 신체 이동 거리·카메라 거리(cm)·내용 이해를 계산하지 않는다.
자세 변화 표시만으로 유효 샘플을 무효로 바꾸거나 후보를 제거/추가하지 않는다.

### 추가한 두 특징 — 구현 제안이며 개선 효과 미검증
- 기존 눈꼬리 축의 u/v/meanV 계산은 그대로입니다.
- 같은 눈꼬리 축으로 윗눈꺼풀 두 점과 아랫눈꺼풀 두 점을 투영합니다. upperV/lowerV는 각각 두 점의 평균, midV는 그 중간, gapV는 lowerV-upperV입니다.
- irisMinusMidV = 기존 irisV-midV: 눈꺼풀 중간을 기준으로 눈 폭으로 나눈 상대 위치입니다.
- irisFraction = (irisV-upperV)/(lowerV-upperV): 위아래 눈꺼풀 사이에서 홍채가 차지하는 상대 위치입니다. 두 눈의 평균도 따로 기록합니다.
- 눈꺼풀 간격이2px 미만이거나 뒤집힌 경우 lids.usable=false로 표시하고 두 눈 평균 특징을null로 둡니다. 2px는 진단용 임시 수치이며 검증된 품질 기준이 아닙니다.
- 계산된 ratio를0~1로 잘라서 흔들림을 작게 보이게 하지 않습니다. 눈꺼풀 추정도 오차가 있고 눈을 감을 때 분모가 작아질 수 있으므로 현재 방식보다 나빠질 수도 있습니다.
- 이것은 2D 특징 비교이며 3D 고개 회전 보정이나 화면 시선 좌표 추정이 아닙니다. 새 변환행렬 출력이나 추가 AI 모델은 켜지 않았습니다.

### 확인 방법과 완료 기준
- 같은45cm 조건에서0번 → 새기록 →10번 → 새기록 →9번. 새로고침·창/배율 변경을 하지 않고 각 단계3개, 총9개 파일을 보냅니다.
