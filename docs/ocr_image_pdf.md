# 사진·스캔 PDF 글자 인식 (OCR)

C(황찬혁) 작성, 2026-11-17. 구현과 측정 기록. 점수 정책은 건드리지 않는다.

## 왜 넣었나

재배치(`web/modules/reflow.js`)는 PDF가 **이미 갖고 있는 텍스트 층**(`page.getTextContent()`)만 입력으로
받는다. 사진으로 찍거나 스캔한 PDF는 그 층이 없다. `findImages()`가 그림 위치를 찾아 "그림 — 원본 N쪽."
자리 표시를 끼우기는 했지만 **그림 안의 글자는 읽지 않았다.** 모든 쪽이 그림뿐이면 남는 쪽이 0개가 되어
`pdf_no_text`로 막혔다.

빠져 있던 칸은 하나다:

```
사진 PDF ──[없던 부분: 글자 인식]──> 텍스트 ──[있던 부분]──> 20px 재배치
```

## 어떻게

`web/modules/ocr.js`. 쪽을 캔버스에 그려 Tesseract로 읽고, **`reflow.js`의 `itemsToLines`가 내는 줄과
똑같은 모양**으로 바꿔 넘긴다. 그 뒤 문단 잇기·줄 나눔·쪽 나눔은 텍스트 PDF와 **같은 길**을 탄다.

```
PDF 쪽 → 캔버스(가로 2000px 목표) → Tesseract(kor+eng, LSTM) → 낱말 상자
       → wordsToLines (줄) → linesToParagraphs (문단) → layoutParagraphs (쪽)
```

들어가는 자리는 `pdfManager.open()` 한 군데다. 재배치 결과가 0쪽일 때만 `openByOcr()`로 간다.
`?ocr=0`으로 끄고, `?ocrlang=kor`으로 언어를 바꾼다.

### 인식 결과를 줄로 바꿀 때 한 일

| 문제 | 한 일 | 근거 (실측, 질병관리청 안내문) |
|---|---|---|
| 한글이 음절 상자로 쪼개져 나온다 (`코` `로` `나`) | 상자 간격이 글자 높이의 **40%**를 넘을 때만 띄어쓴다 | 음절 사이 −1~13px, 낱말 사이 21~35px, 글자 높이 40~46px |
| 장식 그림을 글자로 읽는다 (화살표 → `--->ㅋㅋ`) | 줄 평균 확신도 **50%** 미만이면 줄째로 버린다 | 장식 줄 15%, 본문 줄 76~97% |
| 좌우로 나란한 두 단을 **한 줄**로 이어 읽는다 | 글자 높이의 **2.5배**보다 크게 벌어지면 다른 단으로 보고 끊는다 | 단 사이 265px, 글자 높이 40px (6.6배) |

띄어쓰기 규칙이 없으면 `코 로 나 19 예 방 접종 안 내 문`이 나온다. 넣으면
`코로나19 예방접종안내문(학생용)`이 된다.

## 한계 — 발표에서 주장하면 안 되는 것

- **인식이 틀리면 글이 틀린다.** 이 문서에서도 `환자→한자`, `37.5℃→375`, `숨가쁨→7HE`,
  `아세트아미노펜→이네트아미노펜`, `붓거나→봇거나`가 나왔다. 사람이 보고 고칠 길은 아직 없다.
- **두 단의 읽는 순서는 줄 단위로 섞인다.** 한 줄 안에서 섞이는 것은 위 표의 세 번째 항목으로 막았지만,
  왼쪽 단을 끝까지 읽고 오른쪽 단으로 가는 순서까지는 복원하지 않는다. 단을 나눠 읽는 판별은
  `linesToParagraphs`가 x 좌표로 하는데, Tesseract가 두 단을 한 줄로 내놓는 바람에 그 판별이 걸리지 않는다.
- **줄 나눔이 원본과 다르다.** 인식된 낱말 상자에서 다시 만든 것이다.
- 그러므로 **OCR로 연 문서는 읽기 측정 시험용**이고, 봉인은 원본 글자를 보증하지 않는다.
  화면에는 문서를 여는 내내 경고를 띄우고, `session.json`의 `ocr` 항목에 언어·확신도·배율을 남긴다.
- 쪽을 그리는 데 `requestAnimationFrame`을 쓰므로, 인식 중에 **다른 탭으로 옮기면 멈춘다**
  (돌아오면 이어서 한다). PDF.js를 쓰는 다른 자리와 같은 성질이다.

## 텍스트 쪽과 스캔 쪽이 섞인 문서 (2026-11-18 추가)

처음 구현은 **문서 전체에 글이 한 줄도 없을 때만** 인식했다. 그래서 텍스트 쪽 사이에 스캔 쪽이 낀
문서는 그 쪽이 안내도 그림 자리 표시도 없이 빠졌고, 보여 주지도 않은 쪽까지 "모든 페이지 기준 충족"으로
봉인됐다 (3쪽짜리 시험 PDF, 가운데가 스캔: `원본 3쪽 → 10쪽`, 스캔 쪽 글 0줄).

지금은 `reflowDocument`가 **스캔 쪽**(글이 없고 그림이 쪽의 60% 넘게 덮는 쪽)을 `scanPages`로 알려 주고,
`pdfManager`가 그 쪽만 인식해 제자리에 끼운다 (같은 PDF: `원본 3쪽 → 13쪽`, 인식한 글이 앞·뒤 쪽 사이에 들어감).

- 인식한 쪽 번호는 화면 안내와 `session.json`의 `ocr.sourcePages`에 남는다.
- 인식을 껐거나(`?ocr=0`) 자산이 없거나 확신도가 낮아 **못 읽은 쪽은 문서를 막지 않고** 화면에
  "원본 N쪽은 … 글을 보여 주지 못했습니다"로 알리고 `session.json`의 `unreadSourcePages`에 남긴다.
  **봉인은 막지 않는다** — 막을지는 점수 정책이라 팀 합의가 필요하다.
- 못 잡는 경우: 스캔 쪽에 머리말·쪽 번호 같은 **텍스트가 조금이라도 얹혀 있으면** 글이 있는 쪽으로 보고
  인식하지 않는다. 그림이 쪽의 60%를 못 덮는 스캔(여백이 넓은 사진)은 예전처럼 "그림 — 원본 N쪽." 자리 표시가 된다.

## 자산

`--no-ocr`로 건너뛸 수 있다. 건너뛰면 사진 PDF를 열 때 안내만 뜨고 나머지는 그대로 동작한다.
버전은 `docs/dependencies.md`.
